# MR 独立题库

按知识领域组织的一套题库，供 MR 战队平台复用。采用**一个仓库、多个课程目录**，而不是每个语言或组别各建仓库。题目分类与战队组别分离；组别、作业和考核安排由网站管理。

本仓库使用 MIT 许可开源，欢迎通过 Issue 和 Pull Request 共同维护。题面、标准答案、参考代码和判题测试均公开，适合学习和练习。`hidden` 仅表示网站作答界面不展示该用例，不代表仓库读者无法看到；正式考试应另行维护私有题目与测试。内部培训题不在本仓库分发。

## 学习入口

| 题库 | 独有题目 | 共用算法 | 目录题量 | 内容 |
| --- | ---: | ---: | ---: | --- |
| [C语言](catalogs/c.json) | 108 | 0 | 108 | 基础语法、分支循环、数组、函数、指针、结构体、位运算 |
| [C++](catalogs/cpp.json) | 8 | 220 | 228 | 基础语法与通用算法；后续补充标准库和语言专项 |
| [Python](catalogs/python.json) | 8 | 220 | 228 | 基础语法、容器与算法；后续继续补充 Python 专项知识 |
| [STM32单片机](catalogs/stm32.json) | 48 | 0 | 48 | STM32F103 基础、时钟、GPIO、中断、定时器、采样、通信与调试 |

共 **392 道唯一公开练习题**。目录数量不能直接相加，C++ 与 Python 共用 220 道算法题。共用目录中的客观题讲通用算法，编程题同时支持 C++17 / Python 3。

这次只整理上述四类。原系统的硬件电路和通用 MCU（含 RP2040）题仍保留在原项目，没有硬归类到 STM32。不会迁移用户、提交、成绩或网站凭据。

## 仓库结构

```text
bank.json                        总索引、四个学习入口
catalogs/                        课程 → 章节 → 题目 ID，支持引用共用目录
  c.json
  cpp.json
  python.json
  stm32.json
  shared-algorithms.json
questions/                       每题一个 JSON，按领域和章节编号分目录
  c/
  cpp/
  python/
  stm32/
  shared-algorithms/
scripts/validate.py              校验 ID、目录、可见性、题型、测试数据
scripts/build.py                 构建供服务端使用的同步数据包
docs/                            格式、同步约定及来源说明
.github/workflows/validate.yml   每次提交和 PR 自动校验
```

编号目录的含义以 `catalogs/*.json` 的章节名为准。题目可以跨课程引用，不要为了让两个组使用同一题而复制内容。以后新增硬件、机械等课程，可追加目录，无需拆成多个仓库。

## 如何新增或修改

1. 在对应 `questions/<领域>/<章节编号>/` 添加题目文件，参照同类现有题。
2. 设置稳定 `id`、`revision`、`subject`、`chapter`、`visibility`、`task`、`sources`、`origin`、`maintenance`。本仓库只接受 `public` 练习。
3. 在 `bank.json` 添加 ID 与文件路径，并在 `catalogs` 对应章节添加 ID。
4. 修改已有题目时保留 ID，增加 `revision`；移动目录也不改 ID。
5. 运行校验，提交分支，通过 PR 合并至 `main`。

```bash
python3 scripts/validate.py
python3 scripts/build.py
```

需要 Python 3.10+，不依赖第三方包。生成的 `dist/bank.json` 含答案和隐藏用例，仅供服务端使用，不提交 Git、不放到网站静态目录。

当前校验检查格式和引用完整性，不自动执行仓库中的参考程序，也不等价于验证每道题的答案正确性。迁移内容来自已经验证过的 MR_system 题库；历史验证范围见 `docs/` 中的存档。

## 与 MR 网站的关系

**当前完成独立仓库和初始题目整理，网站尚未接入自动拉取。** 本仓库的提交不会自动修改线上题目、已发布作业或成绩。

下一步由网站后台只读拉取指定仓库/分支，固定 commit 后校验、预览和同步；新增题按稳定 ID 去重，修改内容采用版本管理，仓库删除题目不删除历史提交。详见 [同步约定](docs/sync-contract.md)。

原有 `task` 保留网站字段以便后续适配，但 `task.status` 只是迁移时的原值，不能作为未经审核自动发布作业的指令。服务器仍需验证可见性并对学生接口隐藏答案和非公开样例。
