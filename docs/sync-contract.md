# 数据格式与后续同步约定

## 格式 v1

- `bank.json`：`schemaVersion`、稳定仓库 `id`、`entrypoints`、目录映射 `catalogs`、题目映射 `questions`。
- `catalogs/*.json`：`id/name`、章节 `chapters`（排序号、名称、题目 ID 列表）、可复用目录 `includes`。禁止引用循环与重复题目。
- 题目：`id` 永久不变；`revision` 为正整数，内容变更时递增。`subject/chapter` 为知识分类；`visibility` 为 public/internal，必须与 `task.bankVisibility` 一致。
- `task` 保留网站使用的题面、标签、题型、答案、判题配置；不包含用户信息或提交记录。
- `sources` 为技术来源链接；迁移题的 `origin` 记录原项目、文件、原始键与文件 SHA256。新增原创题使用 `origin: {"type": "original", "author": "GitHub用户名", "description": "原创题目与测试的编写说明"}`，无需伪造旧文件校验值。
- `maintenance` 仅供维护者：参考程序、推荐简答小问、原始章节和核验说明。网站学生接口不得返回此字段。

选择题答案为从 0 开始的选项下标字符串。编程题 `judge.languageIds` 使用现有 Judge0 标识：50=C、54=C++、71=Python。`testCases[].hidden` 控制样例和隐藏测试；未完成服务端脱敏前不得直接将题库包提供给浏览器。

## 服务端接入计划（尚未实施）

1. 管理员配置仓库、分支、同步周期和只读凭据。凭据保存在服务端，不能写入此仓库或浏览器。
2. 通过 GitHub API 固定 commit，拉取清单和题目；只处理数据，禁止执行仓库内的脚本。
3. 校验 schema、路径、大小、完整性和题型。任何题失败则整批不导入，保留上次有效版本。
4. 以 `(repository, question.id)` 作为稳定身份，`revision` 和内容哈希用于发现变化。禁止用题目标题或文件路径当唯一身份。
5. 初次接入已有线上题时，使用原项目迁移记录匹配现有 task ID；不能简单重复创建。运行时的 task ID 映射属于网站数据库，不放在题库仓库中。
6. 新题按管理员选定策略导入；变更先显示差异。已引用到作业或已有提交的题目保留旧版本，作业固定版本快照。
7. 删除题目只影响后续可选列表，不删除作答、成绩或已发布作业。内部题不会因进入语言目录而变成公开题。
8. 后台显示最后成功 commit、时间、增改数量与错误；支持立即检查和回退到已验证版本。

`dist/bank.json` 是供未来同步适配器使用的数据包，不是可直接投递给现有网站 API 的请求。当前 GitHub Actions 只校验，不发布、不调用网站接口。

## 开源范围

本公开仓库只收录 `visibility: public` 的练习题，CI 会拒绝内部题。答案、参考代码和所有测试随 MIT 许可公开，`hidden` 仅控制网站 UI 展示；不可依赖本仓库的测试保密来组织正式考试。内部题保留在原 MR_system 项目，后续应使用独立私有来源。
